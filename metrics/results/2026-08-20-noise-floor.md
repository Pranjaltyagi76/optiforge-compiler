## 8. Analysis (written by hand)

**This run measures nothing about the compiler.** Both configurations are `-O2`.
The two binaries are built from the same source by the same compiler with the
same flags, so any difference between their timings is, by construction, entirely
interference from the rest of the machine. That difference **is** the noise
floor (`methodology.md` §3.2), and no result anywhere in this project that is
smaller than it may be reported as a result.

| Program | Same-configuration difference |
|---|---:|
| `biased_branch.of` | **1.00%** |
| `nested_math.of` | 0.72% |
| `recursive_fib.of` | 0.49% |
| `branch_machine.of` | 0.48% |
| `nbody.of` | 0.46% |
| `loop_kernel.of` | 0.36% |
| `branchy.of` | 0.32% |
| `loop_sum.of` | 0.30% |

**Noise floor adopted: 1.0%**, the worst case rather than the average. Taking
the mean here would be optimistic in precisely the situation that matters — the
program whose measurement is least trustworthy is the one whose floor should
govern it.

This is recorded in the [machine spec](../machines/windows-mingw.md) and is the
`--noise-floor` argument passed to every subsequent harness run.

## 9. Anomalies and threats to validity (written by hand)

**`branch_machine.of` breaches the Q-02 spread gate.** Its IQR/median is 5.2% in
*both* halves of this run, against a 3% target, while its same-configuration
median difference is a well-behaved 0.48%. The samples are bimodal — roughly
330 ms or roughly 351 ms — and both halves show the same pattern at the same
points in the session, which makes it CPU frequency drift over the run rather
than anything the program does.

Two consequences, both acted on:

- Interleaving is what keeps this from becoming a fake result. Because the two
  configurations alternate, the drift lands on both equally, which is visible
  here as two nearly identical medians despite the spread.
- **For `branch_machine.of` alone, differences under about 5% are unresolved.**
  This is stated in the machine spec and repeated wherever the program is
  reported. Its Phase 12 result of +15.8% is far outside it.

Note that in the main benchmark session an hour later the same program measured
0.5–1.3% IQR/median. The machine was quieter; the conservative figure is the one
carried forward.

**The Windows power plan is Balanced, not a fixed-frequency governor**, which
`methodology.md` §3.1 asks for. That is very likely the source of the drift
above. It was left as it is: the plan is a machine-wide setting, and the floor
came out under the gate regardless. Recorded rather than argued away.

**Sections 4 and 6 are absent from this page** because the harness omits the
profile-health and IR-reduction tables when no PGO configuration ran. Section 5
and 7 are present but say nothing interesting here — both `-O2` builds are
byte-identical work, so their static counts and compile times match, which is a
weak confirmation that the compiler is deterministic (C-10).
